## Story
**As a** user,
**I want** a **simple, self-contained installer for my operating system**,
**so that** I can easily install and run the ZoteroRAG Desk application without manual setup.

2.  5.3.2: The installers include all necessary Python runtime and application dependencies.
3.  5.3.3: Installation is a straightforward, wizard-driven process requiring minimal user interaction.
4.  5.3.4: The installed application launches successfully and functions as expected on each target OS.

## Dev Notes
This story focuses on packaging the application for distribution. The implementation must follow the guidelines set in the project's architecture documentation.

- **Previous Story Insights**: Story 5.2 introduced the `keyring` library, which has platform-specific dependencies and backends. The build process must correctly bundle and configure `keyring` for each target OS (Windows, macOS, Linux) to ensure secure API key storage functions correctly in the packaged application. Failure to do so could break the application or lead to security vulnerabilities. [Source: `docs/stories/5.2.Implement-Secure-API-Key-Management.story.md`]

- **Tooling**: `PyInstaller` is the mandatory build tool for packaging the application. [Source: `docs/architecture/tech-stack.md`]

- **Automation Script**: All build logic must be contained within a `scripts/build.py` script. This script will automate the PyInstaller process for different platforms. [Source: `docs/architecture/unified-project-structure.md`, `docs/architecture/deployment-and-release-management.md`]

- **Platform-Specific Outputs**: The build script must generate the correct package format for each operating system:
    - **Windows**: A single `.exe` installer.
    - **macOS**: A `.dmg` disk image containing the `.app` bundle.
    - **Linux**: A distribution-agnostic `.AppImage` file.
    [Source: `docs/architecture/deployment-and-release-management.md`]

- **macOS Specifics**: For the macOS build, the `.app` bundle must be code-signed and notarized to comply with Apple's security policies. While full implementation of notarization might be a separate task, the build script should include placeholders or hooks for these steps. [Source: `docs/architecture/deployment-and-release-management.md`]

- **CI/CD Integration**: The `scripts/build.py` script will be executed within a GitHub Actions workflow. It must be runnable from the command line and handle all build steps without user interaction. [Source: `docs/architecture/deployment-and-release-management.md`]

- **Data Files**: The PyInstaller build must be configured to include non-code assets, such as UI icons or other resources located in `src/zoterorag/ui/assets/`.

    - Subtask 2.1: Create the file `scripts/build.py`.
    - Subtask 2.2: Implement the main function that calls PyInstaller with appropriate flags. Use the `subprocess` module to run PyInstaller.
    - Subtask 2.3: Configure the PyInstaller spec to bundle the main entry point (`src/zoterorag/__main__.py`), include necessary data files (assets), and handle hidden imports if any are discovered during testing.
    - Subtask 2.4: Add logic to the script to detect the current OS and apply platform-specific configurations (e.g., icon files, bundle identifiers).

- **Task 3: Implement macOS Specifics (AC: 1)**
    - Subtask 3.1: In `scripts/build.py`, add steps to create a `.dmg` file from the generated `.app` bundle for macOS builds.
    - Subtask 3.2: Add placeholder comments or functions for future code-signing and notarization steps.

- **Task 4: Test Build Locally (AC: 4)**
    - Subtask 4.1: Run the `python scripts/build.py` command on your local development machine.
    - Subtask 4.2: Locate the generated installer in the `dist/` directory.
    - Subtask 4.3: Install and run the application to confirm it launches and core functionality (like Zotero connection and settings) works as expected. Pay close attention to `keyring` related functionality.

- **Task 5: Update Documentation**
    - Subtask 5.1: Add a new section to the main `README.md` file explaining how to build the application from source using the `scripts/build.py` script.

- **Task 6: Basic CI Workflow (Optional but Recommended)**
