# Story 4.4: Implement PDF File Export

## Status
- **Done**

## Story
**As a** user,
**I want** to export the actual PDF files from my search results to a new folder,
**so that** I have a self-contained collection of relevant papers for sharing or external use.

## Acceptance Criteria
1.  4.4.1: An "Export PDFs" button is available on the search results screen.
2.  4.4.2: Clicking the button prompts the user to select a destination folder for the export.
3.  4.4.3: The application creates a new subfolder in the selected destination (e.g., named with the current date/time or a user-provided name).
4.  4.4.4: The application copies all unique PDF files corresponding to the search results into the newly created subfolder.
5.  4.4.5: A notification confirms that the files have been successfully exported and provides the path to the new folder.

## Tasks / Subtasks
- [x] **UI:** Add an "Export PDFs" `QPushButton` to the `search_view.py` widget. (AC: 4.4.1)
- [x] **UI Interaction:** Connect the new button's `clicked` signal to a handler slot in `main_window.py`.
- [x] **Background Task:** Implement the handler to run the export process in a background thread using the existing `Worker` and `QThreadPool` pattern.
    - [x] **File Dialog:** Prompt the user to select a destination directory using `QFileDialog.getExistingDirectory` on the main thread before dispatching the worker.
    - [x] **Export Logic:** Create a core export method.
        - [x] Subtask: Retrieve the list of unique `pdf_file_path`s from the current search results stored in the `AppState`.
        - [x] Subtask: Create a new, uniquely named subfolder in the user's selected destination (e.g., `zotero-export-YYYY-MM-DD_HH-MM-SS`). (AC: 4.4.3)
        - [x] Subtask: Loop through the unique PDF paths and use `shutil.copy2` (to preserve metadata) to copy each file into the new subfolder. (AC: 4.4.4)
    - [x] **Notifications:**
        - [x] Subtask: On success, the worker emits a signal with the path to the new folder; the main window shows a confirmation `QMessageBox`. (AC: 4.4.5)
        - [x] Subtask: On failure (e.g., I/O error, permissions error), the worker emits an error signal; the main window shows an error `QMessageBox`.

## Dev Notes
- **Target Components:**
    - `src/zoterorag/ui/search_view.py`: Add the "Export PDFs" button here.
    - `src/zoterorag/ui/main_window.py`: Orchestrate the feature. Implement the slot to handle the button click and manage the background worker.
- **Threading Model:** This is a file I/O operation that could be slow. It is critical to use the established `Worker`/`QThreadPool` pattern from the architecture to prevent blocking the UI. The `MainWindow` should instantiate a `Worker` to run the export logic.
- **State Management:** The list of search results, which contains the `Document` objects with the necessary `pdf_file_path`, is managed in the `AppState` dataclass within `MainWindow`. The export logic will need to access this state to get the list of files to copy.
- **File Operations:** Use Python's standard `os` and `shutil` libraries for creating directories and copying files. `shutil.copy2` is preferred over `shutil.copy` to preserve file metadata.
- **User Interaction:**
    - Use `QFileDialog.getExistingDirectory` to allow the user to select a folder.
    - Use `QMessageBox.information` for the success notification and `QMessageBox.critical` for error notifications.
