# Story 6.5: Reposition Chunk Count Selector

## Status
Done

## Story
**As a** user,
**I want** the control for selecting the number of search results to be located next to the search button,
**so that** it is easily discoverable and I can adjust it as I refine my search.

## Acceptance Criteria
1. 6.5.1: The `QSpinBox` for selecting the number of chunks to retrieve is removed from its old location.
2. 6.5.2: The `QSpinBox` is positioned on the same row as the main search input field and search button.
3. 6.5.3: A label "Results:" is placed next to the spin box to clarify its purpose.
4. 6.5.4: The search function correctly uses the value from the newly positioned spin box.

## Dev Notes
This story involves a UI layout change within the `SearchTab` component. The goal is to improve usability by grouping the search input field, the result count selector, and the search button together.

- **Relevant Component:** `SearchTab` located in `src/ui/search_tab.py`.
- **Architectural Guidance:** The `Frontend Architecture` section of `architecture.md` specifies that the `SearchTab` should contain the search controls. The `Component Template` for `SearchTab` provides a direct example of the target layout using a `QHBoxLayout` for the search controls. [Source: architecture.md#component-template]
- **File Locations:** All changes should be contained within `src/ui/search_tab.py`. Tests should be added or updated in the `tests/ui/` directory. [Source: architecture.md#project-source-tree]
- **Data Models:** No data models are directly affected by this UI change.
- **Previous Story Insights:** Story 6.1 introduced the tabbed interface, creating the `SearchTab` component that will be modified here. Ensure changes are consistent with the new tab structure.

### Testing
- **Testing Standards:** Per `architecture.md#development-workflow`, all new UI logic should be covered by unit tests using `pytest` and `pytest-qt`.
- **Test file location:** `tests/ui/test_search_tab.py` (create if not exists).
- **Specific Requirements:**
  - A test should verify that the `k_spinbox` and its "Results:" label are now part of a `QHBoxLayout` that also contains the search bar and button.
  - A test should simulate clicking the search button and assert that the `search_triggered` signal is emitted with the integer value currently set in the `k_spinbox`.
