# Story 7.6: Add Retrieval Toggle & Chunk Count Control

## Status
Complete

## Story
**As a** researcher,
**I want** to control whether AI retrieves paper context and how many chunks to include,
**so that** I can balance between detailed context and focused questions.

## Acceptance Criteria
1.  **Retrieval Controls UI**
    - Checkbox labeled "Include search context" in AI Analysis tab
    - Spinbox for "Number of chunks to retrieve" (range: 1-20, default: 5)
    - Spinbox enabled only when checkbox is checked
    - Controls positioned near chat input or top of tab
    - Tooltip explains: "Include relevant paper excerpts in AI analysis"

2.  **Toggle ON Behavior**
    - When checked: retrieve top N chunks from current search results
    - Retrieved chunks prepended to conversation context as system message or user message prefix
    - Chunk context includes: paper title, author, chunk text
    - Context formatted clearly: "Context from search results: [chunks]"

3.  **Toggle OFF Behavior**
    - When unchecked: send only user message to AI (no retrieval)
    - AI receives conversation history but no paper excerpts
    - Allows for general questions not requiring paper context

4.  **Spinbox Functionality**
    - Value changes update number of chunks retrieved on next message
    - Immediate visual feedback on value change
    - Invalid values prevented (clamped to 1-20 range)

5.  **State Management**
    - Toggle state and chunk count stored in session (not persisted across app restarts)
    - Default state on new analysis: toggle ON, chunk count 5
    - State preserved during conversation session

6.  **Integration with Chat**
    - Retrieval happens only when toggle is ON
    - Retrieved context included in API request for that message only
    - Subsequent messages use toggle state at time of sending
    - Clear indication in UI when context was included (optional: show chunk count in message)

7.  **Chat UI Usability**
    - Chat history view must be scrollable to ensure long messages are fully visible.
    - Individual messages (both user and AI) must wrap text and expand vertically to show all content.
    - The user's text input box should have a reasonable minimum height (e.g., 3-4 lines of text) and expand or scroll as the user types a long message.

## Dev Notes
This story involves modifying the UI and the controller logic that handles chat messages.

-   **File Locations**:
    -   **Modify**: `src/zoterorag/ui/ai_analysis_tab.py` to add the new `QCheckBox` and `QSpinBox` controls. [Source: `docs/architecture/frontend-architecture.md`]
    -   **Modify**: `src/zoterorag/ui/main_window.py` (or the class managing the chat logic) to implement the conditional retrieval. This involves checking the state of the new UI controls before calling the `AIService`.

-   **Component Interaction**:
    -   The `AIAnalysisTab` will emit signals or have its state checked by `MainWindow` when a message is sent.
    -   If context retrieval is enabled, the `MainWindow` will first interact with the `SearchService` to get relevant chunks from the last search query. [Source: `docs/architecture/components.md`]
    -   The retrieved `Chunk` data, which includes `document_id`, `content`, and `page_number`, will be used. The `document_id` can be used to look up the `Document`'s title and authors from the `MetadataDBManager`. [Source: `docs/architecture/data-models.md`]
    -   The formatted context and the user's message will then be passed to the `AIService`.

-   **State Management**:
    -   The state for the toggle and spinbox is ephemeral and should be managed within the UI session. It does not need to be saved to the settings file via `SettingsManager`. The default values should be applied each time a new analysis is started. [Source: `docs/architecture/frontend-architecture.md`]
