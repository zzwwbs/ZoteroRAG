## Story
**As a** user with a large library,
**I want** to be able to **cancel an ongoing indexing process**,
**so that** **I don't have to force-quit the application if I start a long operation by mistake**.

## Acceptance Criteria
1.  6.2.1: When indexing begins, the "Start Indexing" button changes to a "Cancel Indexing" button with a distinct visual style (e.g., red background).
2.  6.2.2: Clicking the "Cancel Indexing" button requests a safe stop of the indexing worker thread.
3.  6.2.3: The indexing process stops gracefully after completing the current in-flight item.
4.  6.2.4: The UI provides feedback that the cancellation is in progress and confirms when it is complete.
5.  6.2.5: The index remains in a valid, usable state, containing all items that were successfully processed before the cancellation.

## Dev Notes
- **Core Logic Location**: All backend logic for cancellation should be implemented within `src/zoterorag/core/services/indexing_service.py`.
- **Threading Model**: The `IndexingService` runs on a background `QRunnable` worker managed by the `MainWindow`'s `QThreadPool`. Cancellation must be thread-safe. An `Event` from Python's `threading` module is recommended. [Source: `docs/architecture/frontend-architecture.md`]
- **UI Implementation**:
    - The button state change (text and color) will be managed in `src/zoterorag/ui/index_tab.py`.
    - The signal handling and service calls will be orchestrated in `src/zoterorag/ui/main_window.py`.
- **State Management**: The `is_indexing` state should be expanded or a new state variable added to reflect the "cancelling" and "cancelled" states to provide clear user feedback. [Source: `docs/architecture/frontend-architecture.md`]
- **Data Integrity**: The cancellation must be "graceful." This means the indexing loop should terminate between documents, not in the middle of processing one. This ensures that the metadata database and the vector index remain consistent. [Source: `docs/architecture/components.md`]
