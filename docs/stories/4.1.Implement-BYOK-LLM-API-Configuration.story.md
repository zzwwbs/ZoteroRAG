# Story 4.1: Implement BYOK LLM API Configuration

## Status
Done

## Story
**As a** user,
**I want** to securely enter and manage my OpenAI (or compatible) API key within the application settings,
**so that** I can enable in-app AI analysis.

## Acceptance Criteria
1.  4.1.1: A dedicated section in the application settings allows users to input their LLM API key.
2.  4.1.2: The API key is stored securely (e.g., encrypted at rest) and never transmitted externally by the application itself.
3.  4.1.3: A "Test Connection" button verifies the validity of the entered API key without performing a full analysis.
4.  4.1.4: A toggle switch allows users to enable/disable in-app AI analysis, which is off by default.

## Dev Notes
*   **Previous Story Insights**: No specific insights from previous stories are directly relevant to this story, as it introduces new configuration and UI elements.
*   **Data Models**:
    *   `AppState` (from `src/zoterorag/ui/state.py`): Will need a field to store the state of the AI analysis toggle (e.g., `enable_ai_analysis: bool = False`). [Source: architecture/frontend-architecture.md#state-structure]
    *   `AppSettings` (from `src/zoterorag/config/models.py`): Will need fields for `api_base_url`, `embedding_model`, `chat_model`, and `enable_ai_analysis`. The API key itself is stored separately. [Source: architecture/frontend-architecture.md#state-structure`]
*   **Component Specifications**:
    *   `SettingsManager` (from `src/zoterorag/config/settings_manager.py`):
        *   **Responsibility:** Manages all application settings and user preferences, including external API keys. Ensures secure storage of sensitive data like API keys.
        *   **Key Interfaces:** `get_api_key() -> str`, `set_api_key_securely(key: str) -> None`, `load_settings() -> AppSettings`, `save_settings(settings: AppSettings) -> None`.
        *   **Dependencies:** OS-specific credential management (e.g., `keyring` library), local file I/O for general settings.
        *   **Technology Stack:** Python.
        *   [Source: architecture/components.md#settingsmanager]
    *   `SettingsDialog` (from `src/zoterorag/ui/settings_dialog.py`): This UI component will be responsible for displaying and allowing the user to edit application settings, including the API key and the AI analysis toggle. [Source: architecture/frontend-architecture.md#component-organization]
    *   `MainWindow` (from `src/zoterorag/ui/main_window.py`): Will need to manage the `AppState` and orchestrate the display of the `SettingsDialog`. [Source: architecture/frontend-architecture.md#routing-architecture]
    *   **Styling**: Adhere to existing Qt Styling Sheets for UI elements to ensure visual consistency.
*   **File Locations**:
    *   `src/zoterorag/config/settings_manager.py`: For implementing the `SettingsManager` logic.
    *   `src/zoterorag/ui/settings_dialog.py`: For implementing the UI for settings.
    *   `src/zoterorag/ui/state.py`: For updating `AppState` with the AI analysis toggle state.
    *   `src/zoterorag/config/models.py`: For defining the `AppSettings` dataclass.
*   **Technical Constraints**:
    *   **Secure API Key Storage (NFR3):** User-provided API keys are never stored in plain text. The `SettingsManager` will use the `keyring` library to store keys in the native OS credential manager (e.g., macOS Keychain, Windows Credential Manager, Freedesktop Secret Service). This provides encryption at rest and OS-level protection. [Source: architecture/security-risk-and-mitigation.md#security-measures]
    *   **Data-in-Transit Encryption:** All communication with external OpenAI-compatible APIs will use HTTPS. [Source: architecture/security-risk-and-mitigation.md#security-measures]
    *   **External API Failure (R-03):** The `EmbeddingClient` and `AIService` will implement retry logic for transient errors and provide clear feedback for persistent errors. This implies that the "Test Connection" functionality should leverage similar error handling. [Source: architecture/security-risk-and-mitigation.md#risk-analysis-and-mitigation]
    *   **Auth Flow (External API):** Services (like `EmbeddingClient` and `AIService`) will call `SettingsManager.get_api_key()` to retrieve the key from the OS Credential Store. [Source: architecture/backend-architecture.md#auth-flow-external-api]
    *   **Middleware/Guards:** UI components (e.g., "Analyze with AI" button) will be enabled/disabled based on whether an API key has been configured in the `SettingsManager`. [Source: architecture/backend-architecture.md#middlewareguards`]
*   **API Specifications**:
    *   The "Test Connection" button will likely make a lightweight call to an OpenAI-compatible endpoint. The `/v1/embeddings` endpoint (POST request) could be used with a minimal input to verify connectivity and API key validity. A successful `200` response or specific error codes (`401` for unauthorized) would indicate validity. [Source: architecture/api-specification.md#rest-api-specification]
