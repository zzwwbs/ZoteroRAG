# Story 5.1: Implement Comprehensive Error Handling & Logging

## Status
- Done

## Story
**As a** developer,
**I want** to implement a robust error handling and logging mechanism throughout the application,
**so that** unexpected issues can be gracefully managed and diagnosed.

## Acceptance Criteria
1.  5.1.1: All critical operations (e.g., Zotero DB access, PDF extraction, API calls, index operations) include `try-except` blocks or equivalent error handling.
2.  5.1.2: User-facing error messages are clear, concise, and actionable, avoiding technical jargon.
3.  5.1.3: Detailed technical errors are logged to a file (e.g., `debug.log`) with timestamps and relevant context.
4.  5.1.4: The application remains stable and responsive even when non-critical errors occur.

## Tasks / Subtasks
- [x] **Task 1: Configure Central Logging Service (AC: 3)**
    - [x] Subtask 1.1: Create a new module `src/zoterorag/core/utils/logging_config.py` to encapsulate logging setup.
    - [x] Subtask 1.2: In this module, configure the root logger using Python's `logging` module.
    - [x] Subtask 1.3: Implement a rotating file handler to save logs to a file in the application data directory.
    - [x] Subtask 1.4: Configure log rotation for ~10MB files with 7 backups.
    - [x] Subtask 1.5: Set the default logging level to `INFO`.
    - [x] Subtask 1.6: If the `ZOTERORAG_DEBUG=True` environment variable is set, change the logging level to `DEBUG`.
    - [x] Subtask 1.7: Define a structured log format including timestamp, log level, module name, and message.
    - [x] Subtask 1.8: Import and invoke the logging setup in the main application entry point (`src/zoterorag/__main__.py`).

- [x] **Task 2: Implement Global Exception Handler (AC: 2, 4)**
    - [x] Subtask 2.1: Implement a global exception hook (`sys.excepthook`) in `src/zoterorag/__main__.py`.
    - [x] Subtask 2.2: The hook should catch any uncaught exceptions.
    - [x] Subtask 2.3: Inside the hook, log the full exception traceback to the log file at `ERROR` level.
    - [x] Subtask 2.4: Display a user-friendly `QMessageBox` with a clear, non-technical error message.

- [x] **Task 3: Add Specific Error Handling to Core Services (AC: 1)**
    - [x] Subtask 3.1: Review critical operations in `ZoteroManager` (DB access).
    - [x] Subtask 3.2: Wrap these operations in `try...except` blocks.
    - [x] Subtask 3.3: In the `except` block, log the specific error with context.
    - [x] Subtask 3.4: For operations that can fail without halting the entire application, ensure the error is logged but the process continues.

- [x] **Task 4: Create Unit Tests for Logging and Error Handling (AC: 1, 3)**
    - [x] Subtask 4.1: Create a test in `tests/core/` to verify that the logging service is correctly initialized.
    - [x] Subtask 4.2: Write a test to confirm that log messages are written to the specified log file with the correct format.
    - [ ] Subtask 4.3: Write a test to simulate an exception in a service and verify that it is caught and logged correctly.

## Dev Notes
This story establishes the application's resilience and diagnosability. All logging and error handling should conform to the standards defined in the architecture.

- **Previous Story Insights**: No specific insights from previous stories are directly applicable. This is a foundational, cross-cutting concern.
- **File Locations**:
    - New logging configuration should be at: `src/zoterorag/core/utils/logging_config.py`. [Source: `docs/architecture/unified-project-structure.md`]
    - Central invocation should be in: `src/zoterorag/__main__.py`. [Source: `docs/architecture/unified-project-structure.md`]
    - Error handling will be added to existing services in `src/zoterorag/core/services/` and other managers.
- **Technical Constraints**:
    - Use the standard Python `logging` module. [Source: `docs/architecture/tech-stack.md`]
    - Logs must be stored in the application data directory.
    - Logging must be structured with levels (DEBUG, INFO, WARNING, ERROR, CRITICAL).
    - Log files must rotate based on size (10MB) and time (7-day retention). [Source: `docs/architecture/tech-stack.md`]
    - The application must respect the `ZOTERORAG_DEBUG` environment variable for verbose logging. [Source: `docs/architecture/development-workflow.md`]

### Testing
- **Testing Standards**:
    - All new logic must have corresponding unit tests.
    - Tests should be placed in the `tests/` directory, mirroring the `src/` structure. [Source: `docs/architecture/unified-project-structure.md`]
    - Use `pytest` as the testing framework. [Source: `docs/architecture/tech-stack.md`]
    - Mocks should be used to isolate components, such as mocking file system access when testing logger configuration.
