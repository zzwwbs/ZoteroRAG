# Story 5.4: Implement Comprehensive Settings UI

## Status
- Done

## Story
**As a** user,
**I want** a **clear and organized settings interface**,
**so that** I can easily configure all application parameters, including Zotero path, embedding provider, chunking options, and API keys.

## Acceptance Criteria
1.  5.4.1: A dedicated "Settings" window or tab is accessible from the main application.
2.  5.4.2: All configurable parameters identified in previous epics (e.g., Zotero path, API keys, chunk size, embedding model) are present and clearly labeled.
3.  5.4.3: Changes to settings are saved persistently and applied correctly.
4.  5.4.4: Tooltips or inline help text explain complex settings.

## Dev Notes
This story involves creating a dedicated UI for managing all user-configurable settings. The implementation must interact with the `SettingsManager` to load and persist settings.

- **Previous Story Insights**: Story 5.2 implemented the `SettingsManager` with secure `keyring` storage for API keys. The new Settings UI must use the `set_api_key_securely` and `get_api_key` methods from the `SettingsManager` for handling the API key field. It should not handle the key directly.

- **Component Location**: The new settings window should be implemented in a new file: `src/zoterorag/ui/settings_dialog.py`. It should be a class inheriting from `QDialog`. [Source: `docs/architecture/frontend-architecture.md`]

- **Component Invocation**: The `MainWindow` should be responsible for creating and showing the `SettingsDialog`. An action, such as a "Settings" menu item or a toolbar button, should be added to the `MainWindow` to open the dialog. [Source: `docs/architecture/frontend-architecture.md`]

- **State Management**: The `SettingsDialog` will interact directly with the `SettingsManager` component to load the current settings upon opening and save the modified settings upon closing (e.g., when an "OK" or "Apply" button is clicked). [Source: `docs/architecture/frontend-architecture.md`, `docs/architecture/components.md`]

- **Configurable Parameters**: The UI must provide controls for all parameters defined in the `AppSettings` dataclass. The API key should be handled separately using the secure methods.
    - **Paths**: Zotero Data Path (`zotero_data_path`) - Should include a "Browse" button.
    - **API Config**: API Base URL (`api_base_url`), Embedding Model (`embedding_model`), Chat Model (`chat_model`).
    - **Chunking**: Chunk Size (`chunk_size`), Chunk Overlap (`chunk_overlap`).
    - **Search**: Default Search Results (`default_search_results`).
    - **Features**: Enable AI Analysis (`enable_ai_analysis`) - Likely a checkbox.
    - **UI**: Theme (`theme`) - Dropdown with 'light', 'dark', 'auto'.
    - **Security**: OpenAI API Key - Use a `QLineEdit` with `EchoMode.Password` and interact with `SettingsManager`'s secure methods.
    [Source: `docs/architecture/frontend-architecture.md#state-structure`]

- **UI Implementation**: Use standard PySide6 widgets (`QLineEdit`, `QSpinBox`, `QComboBox`, `QCheckBox`, `QPushButton`) for the input fields. Use `QFormLayout` for a clean, organized layout of labels and controls. [Source: `docs/architecture/frontend-architecture.md`]

- **Testing**: Unit tests should be created in `tests/ui/test_settings_dialog.py`. Tests should mock the `SettingsManager` and verify that:
    - The dialog loads settings correctly into the UI widgets.
    - The dialog calls the `save_settings` and `set_api_key_securely` methods with the correct data when the save action is triggered.
    [Source: `docs/architecture/development-workflow.md`]

## Tasks / Subtasks
- **Task 1: Create the Settings Dialog UI (AC: 1, 2, 4)**
    - Subtask 1.1: Create the new file `src/zoterorag/ui/settings_dialog.py`.
    - Subtask 1.2: Implement a `SettingsDialog` class inheriting from `QDialog`.
    - Subtask 1.3: Use `QFormLayout` to add labeled widgets for all settings specified in the `AppSettings` dataclass.
        - `zotero_data_path`: `QLineEdit` with a `QPushButton` for browsing.
        - `api_base_url`, `embedding_model`, `chat_model`: `QLineEdit`.
        - `chunk_size`, `chunk_overlap`, `default_search_results`: `QSpinBox` with appropriate ranges.
        - `enable_ai_analysis`: `QCheckBox`.
        - `theme`: `QComboBox` with "light", "dark", "auto".
        - API Key: `QLineEdit` with `EchoMode.Password`.
    - Subtask 1.4: Add tooltips (`setToolTip`) to widgets for complex settings like Chunk Size and Overlap.
    - Subtask 1.5: Add "OK", "Cancel", and "Apply" buttons (`QDialogButtonBox`).

- **Task 2: Integrate with SettingsManager (AC: 3)**
    - Subtask 2.1: In `SettingsDialog`, implement a method to load data from a `SettingsManager` instance into the UI widgets.
    - Subtask 2.2: Connect the "OK" and "Apply" buttons to a `save_settings` method.
    - Subtask 2.3: The `save_settings` method should create an `AppSettings` object from the UI values and pass it to `SettingsManager.save_settings()`. It must also call `SettingsManager.set_api_key_securely()` for the API key.
    - Subtask 2.4: The "Cancel" button should close the dialog without saving.

- **Task 3: Connect Dialog to Main Window (AC: 1)**
    - Subtask 3.1: In `MainWindow`, add a menu item (e.g., "File" -> "Settings") or a `QToolButton`.
    - Subtask 3.2: Connect the trigger for this action to a method that creates and opens an instance of `SettingsDialog`.
    - Subtask 3.3: Pass the application's `SettingsManager` instance to the `SettingsDialog` upon creation.

- **Task 4: Implement Unit Tests (AC: 3)**
    - Subtask 4.1: Create the test file `tests/ui/test_settings_dialog.py`.
    - Subtask 4.2: Write a test to verify that the dialog correctly populates its fields from a mock `AppSettings` object.
    - Subtask 4.3: Write a test to verify that clicking "OK" calls the `save_settings` and `set_api_key_securely` methods on a mock `SettingsManager` with the correct data from the UI fields.
