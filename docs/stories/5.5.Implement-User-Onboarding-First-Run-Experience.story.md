# Story 5.5: Implement User Onboarding & First-Run Experience

## Status
- **Done**

## Story
**As a** new user,
**I want** a guided first-run experience,
**so that** I can quickly set up the application and understand its core functionality without needing to read documentation.

## Acceptance Criteria
1.  5.5.1: On the very first launch, a clear onboarding flow guides the user through Zotero directory selection and initial indexing.
2.  5.5.2: Key privacy and cloud usage disclaimers are presented and acknowledged by the user during onboarding.
3.  5.5.3: The onboarding flow culminates in the user being able to perform their first semantic search.
4.  5.5.4: The application provides visual cues or hints for key features (e.g., "Click here to start indexing").

## Tasks / Subtasks
- [ ] **Task 1: Create the Onboarding View UI (AC: 1, 2)**
    - [ ] Create a new file `src/zoterorag/ui/onboarding_view.py`. [Source: `architecture/frontend-architecture.md`]
    - [ ] Implement a `QStackedWidget` or similar to manage the steps of the onboarding process (e.g., Welcome, Zotero Path, Privacy Disclaimer, Finish).
    - [ ] Design a "Welcome" screen that briefly explains the app's purpose.
    - [ ] Add a view for Zotero directory selection, reusing logic from story 1.2 but integrated into the flow.
    - [ ] Create a view to display privacy and cloud usage disclaimers with a checkbox/button for user acknowledgment.
    - [ ] The final screen should provide a "Finish" button.
- [ ] **Task 2: Integrate Onboarding Flow into Main Application (AC: 1, 3)**
    - [ ] In `src/zoterorag/ui/main_window.py`, use a `QStackedWidget` to show either the `OnboardingView` or the main `SearchView`. [Source: `architecture/frontend-architecture.md#Route-Organization`]
    - [ ] On application startup, check a setting (e.g., `onboarding_completed`) via the `SettingsManager`.
    - [ ] If the setting is `False` or not present, display the `OnboardingView`. Otherwise, show the main `SearchView`.
    - [ ] When the user clicks "Finish" in the `OnboardingView`, emit a signal.
    - [ ] The `MainWindow` should connect to this signal, set `onboarding_completed` to `True` in the settings, and switch the `QStackedWidget` to the `SearchView`.
- [ ] **Task 3: Implement Visual Cues (AC: 4)**
    - [ ] After the onboarding is complete and the `SearchView` is shown for the first time, use tooltips or a temporary overlay to highlight key UI elements.
    - [ ] Add a visual cue pointing to the "Start Indexing" button.
    - [ ] Add a visual cue for the main search bar, explaining its purpose.
- [ ] **Task 4: Unit and Integration Testing**
    - [ ] Create `tests/ui/test_onboarding_view.py`.
    - [ ] Write tests to verify that the onboarding view correctly guides the user through each step.
    - [ ] Write a test to ensure the `onboarding_completed` setting is saved correctly.
    - [ ] Write an integration test in `tests/ui/test_main_window.py` to verify that the application shows the correct view (onboarding vs. search) on startup based on the setting.

## Dev Notes
This story focuses on creating a guided setup process for new users. The core components involved are a new `OnboardingView` and modifications to the `MainWindow` to conditionally display it.

### Previous Story Insights
- Story 5.4 implemented the comprehensive settings UI, which is related. The `SettingsManager` is now robust and can be used to persist the `onboarding_completed` flag.

### Data Models
- No new data models are introduced. This story primarily interacts with application settings. [Source: `architecture/data-models.md`]

### Component Specifications
- **`OnboardingView` (`src/zoterorag/ui/onboarding_view.py`):** A new `QWidget` that will contain the multi-step onboarding process. It should emit a signal upon completion. [Source: `architecture/frontend-architecture.md#Component-Organization`]
- **`MainWindow` (`src/zoterorag/ui/main_window.py`):** Will be updated to use a `QStackedWidget` to manage showing the `OnboardingView` or the main `SearchView`. It will be responsible for checking the onboarding status with the `SettingsManager`. [Source: `architecture/frontend-architecture.md#Routing-Architecture`]
- **`SettingsManager` (`src/zoterorag/config/settings_manager.py`):** Will be used to get/set a new boolean flag, `onboarding_completed`, to track if the first-run experience has been finished. [Source: `architecture/components.md#SettingsManager`]

### File Locations
- **New UI Component:** `src/zoterorag/ui/onboarding_view.py`
- **Modified UI Component:** `src/zoterorag/ui/main_window.py`
- **Modified Config Component:** `src/zoterorag/config/settings_manager.py` (to add the new setting)
- **New Test File:** `tests/ui/test_onboarding_view.py`
[Source: `architecture/unified-project-structure.md`]

### Technical Constraints
- The onboarding flow must be non-blocking for the UI thread. Any long-running operations like initial indexing should be handled in the background as established in previous stories. [Source: `architecture/frontend-architecture.md#Service-Example`]
- Privacy disclaimers must be clear and require explicit user acknowledgment before proceeding.

### Testing
- **Test File Location:** Tests for the new UI component should be created in `src/tests/ui/test_onboarding_view.py`.
- **Test Standards:** Adhere to `pytest` standards. Use `pytest-qt` for simulating UI interactions (e.g., button clicks).
- **Frameworks:** `pytest`, `pytest-qt`.
- **Specific Requirements:**
    - Mock the `SettingsManager` to test both scenarios: first run (onboarding needed) and subsequent runs (onboarding skipped).
    - Verify that signals are emitted correctly from the `OnboardingView` upon completion.
    - Ensure the main window correctly switches its view in the `QStackedWidget`.
[Source: `architecture/development-workflow.md#E2E-Testing`]
