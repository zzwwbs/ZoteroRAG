### Component Specifications
- **`EmbeddingClient`**: Responsible for handling communication with the external OpenAI-compatible API to generate vector embeddings.
- **Key Interface**: `get_embedding(text: str) -> list[float]`
- **Dependencies**: `SettingsManager`, `requests` (or similar HTTP client).
- **Location**: `src/zoterorag/core/services/embedding_client.py`
- [Source: `architecture/components.md#EmbeddingClient`]
- [Source: `architecture/unified-project-structure.md`]

### API Specifications
- **Endpoint**: `POST /v1/embeddings`
- **Request Body**:
  ```json
  {
    "input": ["<text_chunk>"],
    "model": "text-embedding-ada-002"
  }
  ```
- **Authentication**: `Authorization: Bearer <USER_API_KEY>`
- **Success Response (200)**:
  ```json
  {
    "data": [{"embedding": [0.1, 0.2, ...], "index": 0}],
    "model": "...",
    "usage": {"prompt_tokens": ..., "total_tokens": ...}
  }
  ```
- **Error Responses**: 400 (Bad Request), 401 (Unauthorized), 429 (Too Many Requests).
- [Source: `architecture/api-specification.md`]

### Technical Constraints
- **Language**: Python 3.13+
- **HTTP Client**: `requests`
- **Authentication**: The client must retrieve the API key from the `SettingsManager`. The full implementation of secure key storage is out of scope for this story, but the interface call must be present.
- [Source: `architecture/tech-stack.md`]
- [Source: `architecture/backend-architecture.md#Auth-Flow-External-API`]

### Testing
- Unit tests must be created in `tests/core/services/`.
- The `requests` library should be mocked to avoid making actual network calls during tests. `unittest.mock` is the preferred tool.
- Tests should cover successful calls, auth header construction, and specific error conditions (401, 429, network failure).
- [Source: `architecture/tech-stack.md#Backend-Testing`]
- [Source: `architecture/coding-standards.md#Testability`]
