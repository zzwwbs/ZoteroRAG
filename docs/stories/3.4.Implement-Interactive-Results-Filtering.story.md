# Story 3.4: Implement Interactive Results Filtering

## Status
Done

## Story
**As a** user,
**I want** to be able to click on a paper in the "Papers" view to filter the "Chunks" view,
**so that** I can focus on the results from a single document.

## Acceptance Criteria
1.  3.4.1: Clicking a paper in the "Papers" view updates the "Chunks" view to show only the chunks from that selected paper.
2.  3.4.2: The UI provides a clear way to remove the filter and return to viewing all chunks.
3.  3.4.3: The application includes a button next to each paper and/or chunk to "Open full PDF", which opens the corresponding PDF file in the system's default viewer.

## Tasks / Subtasks
- [x] **Implement Paper Selection in `PaperListView`** (AC: 3.4.1)
  - [x] Modify `PaperListView` to make individual paper entries clickable.
  - [x] Implement a signal (e.g., `paper_selected = Signal(Document)`) in `PaperListView` that emits the selected `Document` object when a paper is clicked.
  - [x] Add a "Clear Filter" mechanism (e.g., a button or a way to deselect) in `PaperListView` or `MainWindow` that emits a signal to clear the `selected_paper`.
- [x] **Update `AppState` and `ChunkListView` based on selection** (AC: 3.4.1, 3.4.2)
  - [x] Add `selected_paper: Optional[Document] = None` to `AppState` in `src/zoterorag/ui/state.py`.
  - [x] In `MainWindow`, connect `PaperListView.paper_selected` signal to a slot that updates `AppState.selected_paper`.
  - [x] In `MainWindow`, implement logic to filter the `search_results` based on `AppState.selected_paper`'s `document_id`.
  - [x] Implement a method in `ChunkListView` (e.g., `update_chunks(chunks: List[Chunk])`) to display the filtered list of chunks.
  - [x] Ensure `MainWindow` triggers `ChunkListView.update_chunks` whenever `AppState.selected_paper` changes or is cleared.
- [x] **Implement "Open full PDF" functionality** (AC: 3.4.3)
  - [x] Add a button or context menu option (e.g., in `PaperListView` or `ChunkListView` or next to each result) to "Open full PDF".
  - [x] When activated, retrieve the `pdf_file_path` from the corresponding `Document` object.
  - [x] Implement a function (e.g., in `MainWindow` or a utility) to open the PDF file using the system's default viewer (e.g., `os.startfile` on Windows, `open` on macOS, `xdg-open` on Linux, or `subprocess.Popen`).
  - [x] Ensure this operation is non-blocking to keep the UI responsive, potentially using `QThreadPool` and `QRunnable` for the `subprocess` call.
  - [x] Add error handling for cases where the PDF file is not found or cannot be opened.

## Dev Notes
*   **Previous Story Insights**: No specific insights from previous stories are directly relevant to this UI interaction story, as it builds on the display of results from Story 3.3.
*   **Data Models**:
    *   `Document` dataclass: Contains `pdf_file_path` which will be needed for "Open full PDF" functionality. [Source: architecture/data-models.md]
    *   `Chunk` dataclass: Contains `document_id` to link chunks to their parent documents for filtering. [Source: architecture/data-models.md]
    *   `AppState` (from `src/zoterorag/ui/state.py`): Will need a `selected_paper` attribute (e.g., `Optional[Document]`) to store the currently selected paper for filtering. The `search_results` in `AppState` will need to be structured to easily filter by `document_id`. [Source: architecture/frontend-architecture.md]
*   **Component Specifications**:
    *   `PaperListView` (`src/zoterorag/ui/paper_list_view.py`): This widget will display the list of source documents. It needs to emit a signal when a paper is clicked, passing the `Document` object or its ID. [Source: architecture/frontend-architecture.md, architecture/components.md]
    *   `ChunkListView` (`src/zoterorag/ui/chunk_list_view.py`): This widget will display the text chunks. It needs a method to update its display based on a filtered list of chunks or a `selected_document_id`. [Source: architecture/frontend-architecture.md, architecture/components.md]
    *   `MainWindow` (`src/zoterorag/ui/main_window.py`): This will manage the `AppState` and orchestrate the filtering. It will connect the `PaperListView`'s selection signal to a slot that updates the `AppState.selected_paper` and then triggers an update in the `ChunkListView`. [Source: architecture/frontend-architecture.md]
*   **File Locations**:
    *   `src/zoterorag/ui/paper_list_view.py`: For implementing the clickable papers and emitting signals.
    *   `src/zoterorag/ui/chunk_list_view.py`: For updating the displayed chunks based on filters.
    *   `src/zoterorag/ui/main_window.py`: For state management and connecting signals/slots.
    *   `src/zoterorag/ui/state.py`: For updating the `AppState` with `selected_paper`.
*   **Technical Constraints**:
    *   **UI Thread Safety**: All UI updates must occur on the main thread. Opening a PDF (which might be a blocking operation) should be handled in a non-blocking way, potentially using `QThreadPool` and `QRunnable` as described in the Frontend Services Layer. [Source: architecture/coding-standards.md, architecture/frontend-architecture.md]
    *   **Signals & Slots**: Use PySide6's signal and slot mechanism for communication between UI components. [Source: architecture/coding-standards.md]
    *   **External Process**: Opening a PDF will involve launching an external process (system's default PDF viewer). Python's `subprocess` module can be used for this.

### Code Quality Assessment

**Critical Fix Applied During Review:**
- **Qt Role Issue**: Fixed incorrect use of role 0 (`Qt.DisplayRole`) for storing data, which was clearing item text
- **Solution**: Changed to `Qt.UserRole` for data storage, preserving `DisplayRole` for text display
- This is a common Qt pitfall - role 0 is reserved for display text
