# Story 7.5: Implement Chat Message Handling & API Integration

## User Story

As a user, I want my chat messages to be processed by AI with conversation context, so that I can have meaningful back-and-forth discussions about my research.

## Acceptance Criteria

1.  **Message Processing**
    -   User input captured from text field.
    -   Input validated (not empty, reasonable length).
    -   User message immediately displayed in chat.
    -   Input field cleared after sending.
2.  **Conversation Context**
    -   Previous messages included in API request for context.
    -   Context limited to a reasonable size (e.g., last 10 messages or 4000 tokens).
    -   System message or initial prompt includes instructions about research analysis.
    -   Conversation context maintained for session duration.
3.  **API Integration**
    -   `AIService` called with user message + conversation history.
    -   Response handling for streaming (if supported) or complete responses.
    -   Partial responses displayed as they arrive (streaming) or full response shown after completion.
    -   Error handling for API failures, rate limits, and timeouts is implemented, displaying a clear error message to the user within the chat interface.
4.  **Response Display**
    -   AI responses appear in chat with proper formatting.
    -   Markdown support for formatted responses is recommended.
    -   Code blocks, lists, bold/italic rendered appropriately.
    -   Long responses wrapped and scrollable.
5.  **Token Tracking**
    -   Token usage recorded for each chat message exchange.
    -   Status bar token display updated after each interaction.
    -   Token usage signals emitted with correct model and provider info.

### Data Models

-   **Chat Messages**: The conversation history must be formatted for the API as a list of dictionaries: `[{"role": "user", "content": "..."}, {"role": "assistant", "content": "..."}]`. [Source: `docs/architecture/api-specification.md`]
-   **Token Usage**: API interactions must create and record `TokenUsage` objects. The `TokenUsage` dataclass is defined in `docs/architecture/data-models.md`.

```python
from dataclasses import dataclass
from datetime import datetime

@dataclass
class TokenUsage:
    id: int
    timestamp: datetime
    operation: str  # "embedding" or "chat_completion"
    tokens_used: int
    model: str
    estimated_cost_usd: float
```

### API Specifications

-   **Endpoint**: All chat interactions will use the `POST /v1/chat/completions` endpoint.
-   **Request Body**: The request must include `messages` and `model`. The `messages` array must contain the conversation history.
-   **Authentication**: The `AIService` is responsible for retrieving the API key from `SettingsManager` and including it as a Bearer token in the `Authorization` header.
-   **Response Payload**: The AI's response content will be in `choices[0].message.content`. Token usage is reported in the `usage` object of the response.
-   [Source: `docs/architecture/api-specification.md`]

### Component Specifications

-   **`AIService`**: This service must be updated to handle chat interactions. A new method, `chat(messages: list[dict])`, or an updated `analyze()` method should be implemented to call the chat completions API. It will receive the message history from the UI layer. [Source: `docs/architecture/components.md`]
-   **`ai_analysis_tab.py`**: This UI component is responsible for managing the chat interface. It will capture user input, maintain the session's conversation history, and display user and assistant messages. [Source: `docs/architecture/frontend-architecture.md`]
-   **`main_window.py`**: The main window will orchestrate the interaction. It should connect the "send" signal from the `ai_analysis_tab` to a handler method. This handler will call the `AIService` in a background thread using `QThreadPool` to keep the UI responsive. The results from the service are then sent back to the UI for display. [Source: `docs/architecture/frontend-architecture.md`]

## Tasks / Subtasks

1.  **Update `AIService` for Chat (AC: 3, 5)**
    -   In `src/zoterorag/core/services/ai_service.py`, create a new method `def chat(self, messages: list[dict]) -> tuple[str, TokenUsage]:`.
    -   This method should call the `POST /v1/chat/completions` endpoint using an HTTP client. [Ref: `api-specification.md`]
    -   It must construct the request body with the `messages` history.
    -   It must handle API responses, extracting the assistant's message and token usage data.
    -   Implement error handling for API failures.
    -   Ensure it returns both the response content and a `TokenUsage` object.

2.  **Implement Conversation Management in UI (AC: 1, 2)**
    -   In `src/zoterorag/ui/ai_analysis_tab.py`, add a list attribute (e.g., `self.conversation_history`) to store the message history for the current session.
    -   When the user sends a message, append `{"role": "user", "content": user_input}` to the history.
    -   Implement logic to limit the context size (e.g., keep only the last 10 messages).
    -   After receiving a response from the `AIService`, append `{"role": "assistant", "content": ai_response}` to the history.
    -   Clear the input field after the message is sent.

3.  **Integrate UI with `AIService` (AC: 1, 3)**
    -   In `src/zoterorag/ui/main_window.py`, create a handler method (e.g., `handle_chat_message(self, message: str)`).
    -   Connect the "send" signal from `ai_analysis_tab.py` to this handler.
    -   The handler should retrieve the current conversation history from the `ai_analysis_tab`.
    -   Use the `QThreadPool` pattern (as defined in `frontend-architecture.md`) to call the `AIService.chat()` method in a background thread.
    -   Create signals to handle the successful response and any potential errors.

4.  **Display AI Response and Track Tokens (AC: 4, 5)**
    -   Create a slot in `main_window.py` connected to the success signal from the background worker.
    -   This slot will call a method in `ai_analysis_tab.py` to display the new AI message in the chat view.
    -   The slot will also emit a signal to update the token usage widget in the status bar with the `TokenUsage` object returned from the `AIService`.
    -   Consider adding basic Markdown rendering support for the AI response display if time permits.

5.  **Write Unit and Integration Tests (AC: All)**
    -   Create `tests/core/test_ai_service.py` and add tests for the `chat` method, mocking the `requests` call.
    -   In `tests/ui/test_ai_analysis_tab.py`, test the conversation history management logic.
    -   Add an integration test to verify that the signal from the UI correctly invokes the `AIService` and that the response is displayed. [Ref: `testing-strategy.md`]
