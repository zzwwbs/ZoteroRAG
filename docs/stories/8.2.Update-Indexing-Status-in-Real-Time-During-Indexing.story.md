# Story 8.2: Update Indexing Status in Real-Time During Indexing

## Status
Done

## Story
**As a** user,
**I want** to see each paper's status update in real-time as indexing progresses,
**so that** I can monitor progress and identify problems immediately.

## Acceptance Criteria
1.  **Status Updates During Indexing**: As IndexingService processes each paper, status changes from "Not Indexed" to appropriate final status. Updates are visible in the UI within 1 second of processing completion, and the UI remains responsive.
2.  **Success Case**: Successfully indexed papers change status to "Indexed" (green checkmark).
3.  **No PDF Case**: Papers without attached PDFs change status to "No PDF" (yellow warning).
4.  **PDF Error Case**: Papers with PDF processing failures change status to "PDF Error" (red X).
5.  **Concurrent Indexing Handling**: Status updates don't conflict or race if indexing is parallel.
6.  **Re-indexing Behavior**: Statuses reset or update correctly when re-indexing is triggered.

```python
def update_status(self, zotero_key: str, status: str) -> None:
    """Update a single item's status if present."""
    row = self._key_to_row.get(zotero_key)  # O(1) lookup
    if row is None:
        return
    self._statuses[zotero_key] = status
    index = self.index(row, 3)
    self.dataChanged.emit(index, index, [Qt.DisplayRole, Qt.ForegroundRole])
```

#### ✅ AC5: Thread-Safe Communication

**Implementation**: `main_window.py` lines 710-736
```python
class _IndexingWorkerSignals(QObject):
    progress = Signal(dict)
    finished = Signal()
    token_usage = Signal(object)
    status = Signal(dict)  # ⭐ Real-time status updates

class _IndexingRunnable(QRunnable):
    def run(self) -> None:
        try:
            self._service.set_status_callback(self.signals.status.emit)  # Bridge callback to signal
            self._service.start_indexing(self._scope)
        finally:
            self._service.set_status_callback(None)  # Cleanup
```

**Qt Signal/Slot Mechanism**:
- Line 305: `worker.signals.status.connect(self._handle_index_status_update)`
- Signals automatically queued between threads by Qt framework
- UI updates always execute in main GUI thread

**Validation Method**: Code review + architecture analysis
- ✅ Qt's signal/slot mechanism is inherently thread-safe
- ✅ Proper callback setup/teardown in worker lifecycle
- ✅ No direct cross-thread calls to UI components

**Status**: PASS
