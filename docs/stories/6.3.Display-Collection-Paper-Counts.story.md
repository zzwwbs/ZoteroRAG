### **User Story**

As a **user**,
I want to **see the number of papers in each Zotero collection before I start indexing**,
so that **I can make an informed decision about the scope of the indexing job**.

### **Acceptance Criteria**

1.  **6.3.1:** The "Entire Library" radio button in the Index tab displays the total number of papers (e.g., "Entire Library (1234 papers)").
2.  **6.3.2:** The collections dropdown list displays the paper count next to each collection's name (e.g., "Cognitive Psychology (87 papers)").
3.  **6.3.3:** The counts are retrieved via an efficient database query.
4.  **6.3.4:** Collections with zero papers are clearly marked (e.g., "History of Science (0 papers)").

### **Dev Notes**

This story involves modifying the `Index` tab to display paper counts for the entire library and for each individual collection. The logic for retrieving these counts should be implemented within the `ZoteroManager` component.

**Data Models & Components:**

*   **`ZoteroManager`**: This component is responsible for all interactions with the Zotero database. It must be updated to include methods for fetching paper counts. [Source: `docs/architecture/components.md`]
    *   A new method, `get_collection_paper_counts() -> dict[int, int]`, should be added to map `collection_id` to its paper count.
    *   A new method, `get_total_paper_count() -> int`, should be added to get the total number of papers.
*   **`Index Tab (index_tab.py)`**: This UI component will consume the new methods from `ZoteroManager` to update its display. [Source: `docs/architecture/frontend-architecture.md`]
*   **`Zotero Database`**: The queries will be performed on the user's `zotero.sqlite` file. The queries should be efficient. [Source: `docs/architecture/backend-architecture.md`]

**File Locations:**

*   **Core Logic:** `src/zoterorag/core/services/zotero_manager.py` (or similar, based on final implementation of `ZoteroManager`).
*   **UI Logic:** `src/zoterorag/ui/index_tab.py`.

**Technical Implementation Details:**

*   The `ZoteroManager` will need to execute SQL queries against the `zotero.sqlite` database.
    *   To get the total paper count, a query like `SELECT COUNT(DISTINCT itemID) FROM items WHERE itemTypeID NOT IN (1, 14)` (excluding notes and attachments) might be appropriate.
    *   To get counts per collection, a query involving `collectionItems` and `items` tables will be needed, such as `SELECT c.collectionID, COUNT(ci.itemID) FROM collections c LEFT JOIN collectionItems ci ON c.collectionID = ci.collectionID GROUP BY c.collectionID`.
    *   These queries are illustrative; the final implementation must be robust.
*   The `IndexTab` in the UI will call these new `ZoteroManager` methods upon initialization to populate the UI elements.
*   The UI text for the radio button and dropdown items must be formatted to include the counts as specified in the acceptance criteria.

5.  **Review and Test**:

    *   Ensure the application handles cases where the Zotero database is not found or is invalid.
