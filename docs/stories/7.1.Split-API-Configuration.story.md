# Story 7.1: Split API Configuration for Embedding vs Chat Models

## Status
Complete

## Story
**As a** researcher,
**I want** to configure separate AI providers for embedding generation and chat analysis,
**so that** I can optimize my costs and use the best model for each purpose.

## Acceptance Criteria
1.  **Settings Schema Extended**: Settings include separate fields for embedding and chat configurations (`embedding_provider`, `embedding_model`, `embedding_api_key`, `embedding_base_url`, `chat_provider`, `chat_model`, `chat_api_key`, `chat_base_url`). The `base_url` fields are intended for custom OpenAI-compatible endpoints.
2.  **Settings UI Updated**: The settings dialog shows two distinct, clearly separated configuration sections for "Embedding" and "Chat".
3.  **UI Delivers Clarity**: The UI includes help text clarifying that the custom endpoints must be OpenAI-compatible.
4.  **Configuration Migration**: On first launch after upgrade, existing general API settings are copied to both new `embedding_*` and `chat_*` fields.
5.  **Service Integration**: `EmbeddingClient` is constructed using `embedding_*` settings, and `AIService` is constructed using `chat_*` settings.
6.  **Validation**: Both configurations are validated before saving, with clear error messages for failures.

## Dev Notes
- **Architectural Constraint**: The solution MUST leverage the existing OpenAI-compatible API clients (`EmbeddingClient`, `AIService`). No new logic for different API structures should be introduced. The goal is to allow users to point the existing clients to different OpenAI-compatible endpoints (e.g., local LLMs, other cloud providers with compatible APIs).

This story refactors the application's settings to allow for more granular control over AI service configurations. The hotfix for story 6.6 already laid some groundwork by making the settings tab functional, which will be built upon here.

- **Previous Story Insights**: Story 6.6 introduced detailed token tracking and a functional `SettingsTab`. This story directly impacts the `SettingsManager` and the `SettingsDialog` which were touched in that hotfix. The separation of `embedding` and `chat_completion` operations in the `TokenUsage` model aligns with the goal of this story.

- **Data Models**:
  - The `AppSettings` dataclass in `src/zoterorag/config/models.py` must be updated. [Source: docs/architecture/frontend-architecture.md#state-structure]
  - No changes are expected for the database models (`Document`, `Chunk`, etc.). [Source: docs/architecture/data-models.md]

- **API Specifications**:
  - The application will continue to interact with OpenAI-compatible APIs as defined.
  - `EmbeddingClient` will use the `embedding_*` configuration to call the `/v1/embeddings` endpoint. [Source: docs/architecture/api-specification.md]
  - `AIService` will use the `chat_*` configuration to call the `/v1/chat/completions` endpoint. [Source: docs/architecture/api-specification.md]

- **Component Specifications**:
  - `SettingsManager`: Core component for this story. It needs to handle loading, saving, and migrating the new split configuration. [Source: docs/architecture/components.md#settingsmanager]
  - `EmbeddingClient`: Will now be configured exclusively with `embedding_*` settings. [Source: docs/architecture/components.md#embeddingclient]
  - `AIService`: Will now be configured exclusively with `chat_*` settings. [Source: docs/architecture/components.md#aiservice]
  - `SettingsDialog` (UI): Requires significant layout changes to present the split configuration clearly to the user. [Source: docs/architecture/unified-project-structure.md]

- **File Locations**:
  - Settings model: `src/zoterorag/config/models.py`
  - Settings logic: `src/zoterorag/config/settings_manager.py`
  - Settings UI: `src/zoterorag/ui/settings_dialog.py`
  - Service instantiation: `src/zoterorag/ui/main_window.py`

### Testing
- **Testing Standards**: All new logic must be covered by unit tests using `pytest`. [Source: docs/architecture/tech-stack.md]
- **Test file locations**:
  - `tests/config/` for `SettingsManager` tests.
  - `tests/core/` for service instantiation tests.
- **Specific Requirements**:

  - Tests should confirm that `EmbeddingClient` and `AIService` receive the correct, distinct configuration dictionaries upon creation.
