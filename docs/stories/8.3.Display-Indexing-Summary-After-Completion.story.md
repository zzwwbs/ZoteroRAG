## Story
**As a** user,
**I want** to see a summary of indexing results after completion,
**so that** I understand what was processed and can quickly identify any issues.

## Acceptance Criteria
1.  **Summary Display Location**: A summary appears directly below the "Start Indexing" button in the Index tab.
2.  **Summary Content**: The summary displays counts for total papers processed, successfully indexed, papers with no PDF, and errors. Example: "Processed: 50 | ✅ Indexed: 45 | ⚠️ No PDF: 3 | ❌ Errors: 2".
3.  **Summary Timing**: The summary appears immediately after the indexing process completes (or is cancelled).
4.  **Summary Lifecycle**: The summary is cleared/hidden when a new indexing operation begins. It is not persisted between application sessions.
5.  **Visual Design**: The summary uses color-coded text and icons (✅, ⚠️, ❌) that are consistent with the status column in the paper list.
6.  **Edge Cases**: The summary correctly reports results for a cancelled job, and shows an appropriate message if no papers were selected for indexing.

## Dev Notes
This story builds directly on the real-time update mechanism from Story 8.2. The `MainWindow` will act as the controller, accumulating status counts from the `paper_processed` signal and then using the `finished` signal from the indexing worker to trigger the final summary display.

- **Previous Story Insights**: Story 8.2 introduced the `_IndexingRunnable` worker with `paper_processed` and `finished` signals, and a handler in `MainWindow` for real-time UI updates. We will augment this handler to count statuses and add a new handler for the `finished` signal.
- **Data Models**: No changes to data models are required for this story.
- **Component Specifications**:
    - `IndexTab`: Will be enhanced with a `QLabel` for the summary and a public method to update it. [Source: docs/architecture/components.md#zoterorag-desk-application-main-ui]
    - `MainWindow`: Will manage the state of the indexing run (the counts) and connect the worker's `finished` signal to a new slot that formats and pushes the summary to the `IndexTab`. [Source: docs/architecture/frontend-architecture.md#state-management-patterns]
- **File Locations**:
    - `src/zoterorag/ui/index_tab.py`: Add UI element and update method.
    - `src/zoterorag/ui/main_window.py`: Add state counters and signal handling logic.
    [Source: docs/architecture/unified-project-structure.md]
- **Technical Constraints**: The summary generation and UI update must happen on the main UI thread. The existing signal/slot mechanism already ensures this.

### Testing
