# Story 6.6: Add API Token Usage Transparency

## Status
Done

## Story
**As a** user providing my own API key,
**I want** to see how many tokens are being used,
**so that** I can understand and trust the application's usage of the API.

## Acceptance Criteria
1. 6.6.1: All API calls (for embedding and AI analysis) record the number of tokens used.
2. 6.6.2: A `TokenUsageWidget` is added to the "AI Analysis" tab.
3. 6.6.3: The widget displays the total tokens consumed for the current session.
4. 6.6.4: The widget provides a breakdown of API calls by type (e.g., "Embedding Calls", "AI Analysis Calls").
5. 6.6.5: A persistent counter in the main window's status bar shows the running total tokens for the session.
6. 6.6.6: A clear disclaimer is included, stating that counts are session estimates and may differ from provider billing.

## Dev Notes
This story introduces cost and token tracking for external API calls. It requires changes across the full stack.

- **Data Layer:**
  - A new table, `token_usage`, must be created. The schema is defined by the `TokenUsage` dataclass in `docs/architecture/data-models.md`.
  - A new `TokenUsageRepository` will be required to abstract database operations for this table. [Source: docs/architecture/backend-architecture.md#data-access-layer-repository-pattern]
- **API Clients & Services:**
  - `EmbeddingClient` and `AIService` must be updated to extract the `usage` object from API responses as specified in `docs/architecture/api-specification.md`.
  - These clients will be responsible for creating the `TokenUsage` object.
  - Services using these clients must persist the `TokenUsage` object to the database.
- **Cost Calculation:**
  - Out of scope for this story. Only token counts are tracked and displayed.
- **Frontend Components:**
  - A new `TokenUsageWidget` will be created at `src/zoterorag/ui/token_usage_widget.py`. [Source: docs/architecture/unified-project-structure.md]
  - This widget will be placed in the `AIAssistantTab`. [Source: docs/architecture/frontend-architecture.md#component-organization]
  - The `MainWindow` status bar will be updated to show a running token total.
- **State Management:**
  - The `MainWindow` should manage the flow of `TokenUsage` data, likely via signals emitted from the service layer (when a background API call completes) and connected to slots in the UI (`TokenUsageWidget` and `MainWindow` status bar). [Source: docs/architecture/frontend-architecture.md#state-management-patterns]

### Testing
- **Testing Standards:** Per `docs/architecture/tech-stack.md`, all new logic should be covered by unit tests using `pytest`.
- **Test file locations:**
  - `tests/core/` for backend logic (cost calculation, repository).

- **Specific Requirements:**
  - Test the cost calculation with various token counts and models.
  - Test that the `TokenUsageWidget` UI updates correctly when its `update_usage` method is called.
  - Ensure API client tests are updated to reflect the new return signature `tuple[..., TokenUsage]`.

def update_usage(self, usage: TokenUsage) -> None:

**Update Mechanism:**
```python
def _handle_token_usage(self, usage) -> None:
    """Update status bar and session totals when token usage is recorded."""
    try:
        tokens = int(getattr(usage, "tokens_used", 0))
    except Exception:
        tokens = 0
    self._session_token_total += max(0, tokens)
    self._token_status.setText(f"Tokens: {self._session_token_total}")
```
