### Story
**As a** user,
**I want** to click a button to get a synthesized answer based on my query and retrieved chunks, with an easily accessible option to adjust the number of chunks,
**so that** I can quickly control the context provided to the AI.

### Acceptance Criteria
1.  **Adjustable Chunk Count:** An input control (e.g., a `QSpinBox`) for adjusting the number of chunks (`N`) is visible in the main UI, near the "Analyze with AI" button. It allows values from 1 to 50 and defaults to 10.
2.  **UI Elements:** The "Analyze with AI" button and the chunk count control are visible and enabled on the search results screen if and only if a valid API key is configured and the in-app analysis feature is toggled on in the settings.
3.  **API Interaction:** Clicking the button triggers the `AIService`. The service sends the original user query and the content of the top `N` retrieved `Chunk` objects (based on the value in the UI control) to the configured OpenAI-compatible API's chat completions endpoint.
4.  **Display Synthesized Answer:** The application displays the LLM's synthesized answer in a dedicated, clearly marked area within the search results UI. This area must handle multi-line text gracefully.
5.  **Inline Citations:** The `AIService` must process the LLM response to include inline citations that map back to the source `Document` and `Chunk`. For example, displaying `[1]`, `[2]`, etc.
6.  **Loading and UI State:** While the `AIService` is awaiting a response, the "Analyze with AI" button and the chunk count control will be disabled, and a visible loading indicator will be displayed in the analysis results area.
7.  **Error Handling:** The `AIService` and the UI must handle potential API errors gracefully. The user must be shown a clear, informative error message, and the UI must return to its pre-analysis state.

### Dev Notes
This story implements the core AI analysis feature. All implementation must align with the established architecture.

-   **Component Interaction:**
    -   The UI (`main_window.py`) invokes `AIService` when the "Analyze with AI" button is clicked.
    -   `AIService` is located at `src/zoterorag/core/services/ai_service.py`.
    -   `AIService` retrieves the API key via `SettingsManager`.
    -   `SettingsManager` is located at `src/zoterorag/config/settings_manager.py`. It must use the `keyring` library for secure API key handling.
-   **Data Flow:**
    1.  User clicks "Analyze with AI".
    2.  The UI reads the number of chunks `N` from the `QSpinBox` control.
    3.  The UI passes the current query and the top `N` `Chunk` objects to `AIService.analyze_chunks` running in a background thread.
    4.  `AIService` constructs a prompt for the LLM. Example prompt structure:
        ```
        Based on the following text chunks, please provide a synthesized answer to the user's query. Reference the chunks using their identifiers (e.g., [CHUNK_1], [CHUNK_2]).

        User Query: "{{user_query}}"

        [CHUNK_1]
        {{chunk_1_content}}

        [CHUNK_2]
        {{chunk_2_content}}
        ...
        ```
    5.  `AIService` sends the request to the LLM API, awaits the response, parses it, and returns the final string with formatted citations.
    6.  The UI thread receives the result and displays it.
-   **Relevant Source Tree:**
    ```plaintext

    ├── config/
    │   └── settings_manager.py       # No changes needed for this story

        └── main_window.py            # To be modified
    ```
