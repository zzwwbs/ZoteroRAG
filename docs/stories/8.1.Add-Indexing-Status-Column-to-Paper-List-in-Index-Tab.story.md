# Story 8.1: Add Indexing Status Column to Paper List in Index Tab

## Status
Done

## Story
**As a** user,
**I want** to see the indexing status of each paper at a glance,
**so that** I can quickly identify which papers are indexed, which have issues, and which haven't been processed yet.

## Acceptance Criteria
1. **Status Column Added**
   - Index tab paper table/list displays new "Status" column.
   - Column positioned prominently (e.g., after Title or Author column).
   - Column header labeled "Status".
   - Column sortable (status priority: PDF Error > No PDF > Not Indexed > Indexed).

2. **Status Values Defined**
   - **Not Indexed** (default): Paper has not been processed by indexing service.
   - **Indexed**: Paper successfully processed and added to vector index.
   - **No PDF**: Paper exists in Zotero but has no attached PDF.
   - **PDF Error**: PDF exists but text extraction or processing failed.

3. **Visual Indicators**
   - Each status has distinct icon and colored text:
     - **Not Indexed**: ⚪ gray circle, gray text "Not Indexed"
     - **Indexed**: ✅ green checkmark, green text "Indexed"
     - **No PDF**: ⚠️ yellow warning triangle, yellow text "No PDF"
     - **PDF Error**: ❌ red X, red text "PDF Error"
   - Icons rendered as Unicode characters or PySide6 icons.
   - Colors accessible (sufficient contrast, colorblind-friendly).

4. **Default State**
   - All papers display "Not Indexed" status initially (on app launch or library load).
   - Status persists across app sessions (stored in metadata database).

5. **Column Behavior**
   - Status column width auto-sized to fit longest status text + icon.
   - Column resizable by user.
   - Column position configurable (user can reorder columns if table supports it).

## Dev Notes
This story focuses on adding a visual indicator for the indexing status of each paper. It requires a data model change, a database schema update, and a UI update.

- **Data Model Modification**:
  - The `Document` dataclass in `src/zoterorag/core/data/models.py` must be updated to include the status.
  - **Proposed Change**:
    ```python
    # In Document dataclass
    indexing_status: str = "Not Indexed" 
    ```
  - [Source: `docs/architecture/data-models.md`]

- **Database Schema**:
  - The `documents` table in the application's SQLite database needs a new `indexing_status` TEXT column.
  - This schema change must be handled by a repeatable migration script as defined in Task 2.
  - The "delete the database" approach is not acceptable. The developer agent must implement the migration script to ensure data integrity and process consistency. [Source: `docs/architecture/database-schema.md`]

- **UI Implementation**:
  - The UI changes will be in the widget that displays the list of papers on the "Index" tab. Based on the architecture, this is likely `src/zoterorag/ui/index_tab.py` or a `paper_list_view.py` it contains.   - You will need to add a column to a `QTableWidget` and populate it with custom `QTableWidgetItem`s that have both an icon and styled text.
  - Sorting will require implementing custom logic for the status column, as alphabetical sorting is not sufficient.

- **Previous Story Insights**:
  - Story 7.6 showed that UI and application logic are well-separated. UI changes are in `src/zoterorag/ui/` and state/logic is handled by `MainWindow` or core services. This story should follow that pattern.
