# Story 6.1: Implement Tab-Based Interface

## Status
- **Done**

## Story
**As a** user,
**I want** the application's functions to be organized into separate tabs,
**so that** the interface is less cluttered and I can focus on one task at a time.

## Acceptance Criteria
1.  The main window is organized into a `QTabWidget` with four tabs: "Search", "Index", "AI Analysis", and "Settings".
2.  The "Search" tab contains the search bar, results views (papers and chunks), and the "Analyze with AI" button.
3.  The "Index" tab contains the Zotero library view, indexing scope controls, and the "Start/Cancel Indexing" button.
4.  The "AI Analysis" tab contains the view for displaying synthesized AI results and the token usage widget.
5.  The "Settings" tab is present as a placeholder for future application settings.
6.  The "Search" tab is disabled until the initial library indexing is complete.
7.  After a successful indexing operation, the UI automatically switches focus to the "Search" tab.

## Dev Notes
This story establishes the primary UI structure for the application. All work should be contained within the `src/zoterorag/ui/` directory.

- **File Locations**:
    - `src/zoterorag/ui/main_window.py`: The main application window class `MainWindow` will host the `QTabWidget`.
    - `src/zoterorag/ui/search_tab.py`: New file for the `SearchTab` widget.
    - `src/zoterorag/ui/index_tab.py`: New file for the `IndexTab` widget.
    - `src/zoterorag/ui/analysis_tab.py`: New file for the `AnalysisTab` widget.
    - `src/zoterorag/ui/settings_tab.py`: New file for the `SettingsTab` widget.
    - `[Source: docs/architecture.md#Component Organization]`

- **Component Specifications**:
    - The `MainWindow` is responsible for initializing the `QTabWidget` and managing the application's top-level state, including which tab is active or enabled. `[Source: docs/architecture.md#Component List]`
    - The `MainWindow` will use a `QStackedWidget` to switch between the `OnboardingView` and the main `QTabWidget`. Your implementation should place the new `QTabWidget` inside this existing structure. `[Source: docs/architecture.md#Routing Architecture]`

- **State Management**:
    - The enabling/disabling of the "Search" tab is a form of state management. The `MainWindow` should listen for signals from the core services (like `IndexingService`) to update the UI state. `[Source: docs/architecture.md#State Management Patterns]`
    - A signal should be emitted from the `IndexingService` upon completion, which the `MainWindow` will connect to a slot to perform the UI updates (enabling and switching tabs).

### Testing Standards
- **Testing Standards**:
    - All new UI components should have corresponding tests in the `src/tests/ui/` directory.
    - Use `pytest` and `pytest-qt` for testing PySide6 components.
    - Tests should verify UI state changes in response to signals from core services.
    - `[Source: docs/architecture.md#Development Workflow]`
